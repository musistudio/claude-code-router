## 适用场景

Pi 是一款通过命令行指定供应商与模型的编码 Agent。在 CCR 中它 **仅支持 CLI**，且始终使用 **仅从 CCR 打开时生效**：CCR 生成启动包装器，让 Pi 走 CCR 网关，并使用你选择的供应商与模型。

当你想让 Pi 走任意 CCR 供应商或 Fusion 模型，或运行相互隔离的 Pi 会话时，使用本页。

> 第一次使用 CCR？请先接入供应商和模型。参见[接入供应商](/guides/provider/)与 [Agent 配置总览](/configuration/profiles/)。

## 前置条件

1. CCR Desktop 正在运行，且已配置至少一个供应商与模型。
2. 已安装 Pi（`PATH` 中可用 `pi`）。
3. 进入 **Agent 配置**，点击 **添加配置**。

## CCR 如何接入 Pi

保存一个 Pi 配置时，CCR 会：

- 在配置专属的 Pi agent 目录（`PI_CODING_AGENT_DIR`，默认位于 `~/.pi/agent` 下）写入受管网关配置。
- 生成启动 **包装器**，设置 `PI_CODING_AGENT_DIR` 与独立的会话目录，关闭 Pi 版本检查，再以 `pi --provider <供应商> --model <模型>` 走 CCR 网关。

启动时若 CCR Desktop 网关未运行，`ccr-app` 会启动一个可共享的临时网关服务，并在最后一个并发 Pi 会话退出后停止它。

## 创建配置

1. 在 **Agent 配置** 点击 **添加配置**，选择 **Pi**。
2. 填写 **配置名称**（例如 `Pi - Work`）。
3. 选择 **模型**。
4. 仅当需要非默认的 Pi 可执行文件或想恢复版本检查时，再添加环境变量。
5. **保存**，然后复制并运行配置卡片上的命令。

## 配置项详解

Pi 固定为 **仅从 CCR 打开时生效** 和 **仅 CLI**，这两项不可编辑。可配置的字段为：

| 字段 | 如何配置 | 效果 |
| --- | --- | --- |
| Agent | 选择 **Pi** | 让 CCR 生成 Pi agent 目录、网关配置与包装器。 |
| 配置名称 | 自由文本，例如 `Pi - Work` | 标识该配置，并用于 `ccr-app "<名称>"`。 |
| 启用 | 开关 | 关闭的配置不会被应用，也不会出现在启动入口。 |
| 模型 | 供应商模型或 Fusion 模型 | 作为 `--model` 传给 Pi，即 Pi 每一轮使用的模型。 |
| 环境变量 | 键值对 | 导出到包装器，见下文。 |

## 环境变量

- `CCR_PI_BIN` / `PI_BIN`：当 CCR Desktop 进程的 `PATH` 中找不到 `pi` 时，指定真实可执行文件的绝对路径。
- `PI_SKIP_VERSION_CHECK`：默认为 `1`（跳过版本检查），使包装器干净启动。仅当有意启用检查时才改为其他值。
- CCR 还会自动把网关主机加入 `NO_PROXY`/`no_proxy`，让 Pi 直连本地网关，无需手动配置。

> CCR 自行管理的变量（`PI_CODING_AGENT_DIR`、`PI_CODING_AGENT_SESSION_DIR`、`CCR_PROFILE_SURFACE`）均为保留项——手动设置无效。

## 打开与使用

点击配置卡片上的终端按钮，运行复制出的命令：

```text
ccr-app "Pi - Work"
```

## 多实例

每个配置都有独立的 `id`，以及独立的 `PI_CODING_AGENT_DIR` 和会话目录，因此多个 Pi 配置可同时运行，使用不同的模型或彼此独立的会话历史。

## 验证

1. 运行从配置卡片复制的 `ccr-app` 命令。
2. 在 Pi 中发送一条消息，确认能正常回复。
3. 打开 CCR 的 **请求日志**，确认请求经过了网关。

## 常见问题

- **Pi 用了非预期的模型**：检查 **模型** 字段；包装器始终把它作为 `--model` 传入。
- **找不到 `pi`**：用 `CCR_PI_BIN` 指定真实可执行文件路径。
- **启动时出现版本检查提示**：正常情况下会被跳过；若出现，请将 `PI_SKIP_VERSION_CHECK` 保留为默认值。
- **`/model` 或模型列表为空**：Pi 不使用 `/model` 列表——请在配置上直接设置所需的 **模型**。
