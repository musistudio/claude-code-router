## 审查发现

### F1 · P1 · #1784 在转换前删除可重放的加密推理状态

位置：[executor.ts:908](https://github.com/musistudio/claude-code-router/blob/046315fb30ef470816ddf5647839c17d015639d9/packages/core/src/gateway/upstream/executor.ts#L908)。

`usageAwareOpenAiChatAttemptBody` 对 Chat 和 Responses 目标都会调用这个清理器，后者无条件删除 `redacted_thinking`。但 ai-gateway 的 Anthropic source parser 会把该块解码成 Responses reasoning 的 `id` / `encrypted_content`，它可能正是上一轮 Responses 经 Anthropic 格式返回、下一轮需要重放的状态。转换前删除会使工具调用后续请求丢失上下文；删除非法明文 `content` 不需要同时删除这种状态。

验证：构造含 `redacted_thinking` 和可见文本的 assistant 历史，PR 输出只剩可见文本，保存加密块的断言失败。另核对已安装 ai-gateway 1.0.21 的 source map，确认 source parser 存在 envelope 解码及 encrypted-content 转换路径。

建议：在目标协议边界区分不可重放的明文转换产物与合法加密状态，保留后者；加一组 Responses -> Anthropic -> Responses 的工具续轮回归。

### F2 · P2 · #1784 会误删合法原生 Responses 历史项

位置：[executor.ts:865](https://github.com/musistudio/claude-code-router/blob/046315fb30ef470816ddf5647839c17d015639d9/packages/core/src/gateway/upstream/executor.ts#L865)。

原生请求中的 `{type:"reasoning", id:"rs_existing", summary:[]}` 没有本 issue 所述的非空 `content`，仍被先删除 `summary`，再整项丢弃。`encrypted_content` 是可选字段，不能用它的缺失判断原生项无效。清理器也没有限制来源协议。这与维护者在 #1692 中要求避免的原生 Responses 行为变化相同。

验证：上述输入变成 `input: []`，无损透传断言失败。类型依据为本地 OpenAI SDK 的 `ResponseReasoningItem`：`summary` 为数组，`encrypted_content` 可选。

建议：不要把合法空 summary 当作非法 content；限制转换来源并保留原生请求。当前 #1692 的来源门控比 #1784 更适合 Anthropic 转换场景，不能直接把两者都合入而保留这个前置删除逻辑。

### F3 · P2 · #1786 部分过期的本地目录会隐藏上游新模型

位置：[probe.ts:360](https://github.com/musistudio/claude-code-router/blob/0c070c6201ca9aa947718e94ac98007926f9b1f5/packages/core/src/providers/probe.ts#L360)。

只要本地 OpenCode 目录含任意当前协议的模型，就把实时 `/models` 结果与旧目录做严格交集。缓存仅有 `old-chat`，上游已发布 `old-chat` 与 `new-chat` 时，即使 `forceRefresh: true`，也只返回 `old-chat`。PR 覆盖了“缓存完全没有协议模型”和“旧缓存模型已下架”，没有覆盖“部分旧缓存 + 新上架模型”。

验证：同一用例在 `afba89fa` 基线返回两个模型，在 PR head 只返回旧模型；断言按排序后的集合比较，不依赖返回顺序。

建议：已知协议不匹配的模型可以过滤，未出现在缓存中的实时模型应保留为待分类项，或刷新权威目录后再分类，不能静默丢弃。

### F4 · P2 · #1788 关闭 attribution 的真实子代理失去指定模型路由

位置：[claude-code-router-plugin.ts:86](https://github.com/musistudio/claude-code-router/blob/30e37e684236d73c2ae40e4f9b7e5bbcf7c2ea0e/packages/core/src/gateway/claude-code-router-plugin.ts#L86)。

消息中的子代理标签现在必须同时有 system billing marker 才能被提取。使用 `CLAUDE_CODE_ATTRIBUTION_HEADER=0` 的真实子代理没有该 marker；即使请求带 `x-claude-code-agent-id`、session header 和认证 profile，标签也被忽略。指定 Haiku 的子任务因此落到主 profile 的 Sonnet，标签还会继续进入上游消息。

验证：同一认证 profile + 带标签子任务 fixture，在基线选中 `Provider/claude-haiku`，在 PR head 选中 `Provider/claude-sonnet`。[Claude Code 网关协议文档](https://code.claude.com/docs/en/llm-gateway-protocol)记录了子代理身份 header 和可关闭 attribution 的行为。

建议：保留阻止 classifier / 主会话引用标签误路由的防护，同时提供不依赖可选 billing block 的真实子任务识别方式；补充 attribution 关闭、有标签真实子任务及引用标签 classifier 的对照测试。不是简单恢复无条件扫描任意消息。

### F5 · P2 · #1788 分批迁移仍反复扫描已处理数据

位置：[usage/store.ts:509](https://github.com/musistudio/claude-code-router/blob/30e37e684236d73c2ae40e4f9b7e5bbcf7c2ea0e/packages/core/src/usage/store.ts#L509)。

每轮 `WHERE upstream_outcome='' ORDER BY id LIMIT 500` 从头寻找未迁移行，更新语句也只有 `id <= batchLastId`，没有推进下界或可用的 outcome 索引。分批限制了单次更新行数，却没有限制重复扫描工作；同步执行于数据库打开过程，会阻塞事件循环。

验证：通过 TypeScript AST 提取 PR 原始迁移函数及批大小，在本机 SQLite 内存库执行：

| 历史行数 | 耗时 | SELECT 查询计划 |
| --- | --- | --- |
| 50,000 | 211 ms | SCAN usage_events |
| 100,000 | 795 ms | SCAN usage_events |
| 200,000 | 3,395 ms | SCAN usage_events |

这是简化表的纯内存微基准，不是生产磁盘耗时预测；但数据量翻倍、耗时约四倍，与代码中的重复前缀扫描一致。PR 的小数据分页测试不能排除该问题。

建议：使用递增 id 游标及带下界的更新区间，或者针对待迁移行的索引；保留中断恢复测试，并补大规模迁移 / 已迁移数据库重开测试。

### F6 · P2 · #1790 无条件优先 fallback 模型，导致已知实际响应模型错价

位置：[usage/store.ts:262](https://github.com/musistudio/claude-code-router/blob/6922a7130c66151bfb3fec99655e93b4a43b456e/packages/core/src/usage/store.ts#L262)。

修复 alias 时将价格查询模型改为无条件优先 `fallbackAttribution.model`。如果上游有自己的模型映射 / 路由，响应明确返回另一个已配置价格的实际模型，记录中的 model 是实际模型，但 pricing 却取原请求模型。只有响应确为别名时，回退到 CCR 路由模型才是正确选择。

验证：请求 `requested-model`、响应 `served-model`，两者都有已知价格；前者输入/输出单价为 1/2，后者为 10/20。基线选 10/20，PR head 选 1/2，实际响应 model 仍记录为 `served-model`。

建议：区分可解析的实际响应模型与重写别名；响应模型能定位到有效价格时优先采用，仅在别名 / 未知响应模型情况下使用已解析的路由目标。保留现有 alias 测试，并加入实际响应模型变化测试。

### F7 · P2 · #1773 未解包常见的 details.error，仍隐藏真正失败原因

位置：[error-detail.ts:126](https://github.com/musistudio/claude-code-router/blob/b6d83fd7d7b3503148bfdca572d585cec0b52e9f/packages/core/src/gateway/http/error-detail.ts#L126)。

新增摘要只读取 `attempt.details.message/type/code`，不读取常见的 `attempt.details.error.message`。已安装 ai-gateway 的 handler 将上游 JSON 原样放入 `details`，因此 OpenAI / Anthropic 风格的嵌套错误会漏掉。这是新增增强功能的覆盖缺口，不是声称主分支原来已有完整错误展开功能。

验证：传入 `details:{error:{type:"rate_limit_error",message:"Quota exhausted"}}`，最终 message 仍是 `[upstream_response|429] Upstream request failed.`；包含真实原因的断言失败。现有 10 项测试只覆盖直接字段等形态，全部通过。

建议：受限地展开标准 `error` 包装，并同时覆盖 JSON 与 SSE 的嵌套错误，保留长度限制、幂等性及原始 attempts。
